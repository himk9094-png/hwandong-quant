# 환동퀀트 — 통합 퀀트 대시보드 + 자동매매

국내 주식·코인 퀀트 대시보드(GitHub Pages)와 알림(ntfy), 그리고 서울 서버(AWS Lightsail)에서 도는 자동 실행·자동매매 도우미.
계산은 모두 **전 거래일 종가** 기준이다(장중 실시간 신호가 아님).

## 지금 쓰는 전략 (2026-11 결정)

**슈퍼퀄리티 소형주 20종목 · 분기 리밸런싱 · +20% 익절 → 현금 대기**

1. 4·6·9·12월 첫 거래일 시가에 교체. 대상 = 시총 하위 20% 보통주(거래대금 20일 평균 1억↑, 관리·환기 제외, 최근 1년 🟡 희석 공시 제외)
2. F스코어 3점(최근 4분기 순이익>0, 영업현금흐름>0, 1년간 주식 수 증가 없음) 중 GP/A(매출총이익÷자산) 높은 순 20종목 동일 금액
3. 산 종목마다 **평균단가 × 1.2 지정가 매도 조건주문**(토스가 정규장 동안 감시). 팔리면 다음 리밸런싱까지 현금, 손절 없음

백테스트(2016.4~2026.11, 상장폐지 포함·비용 반영): 연 19.5% / 최대낙폭 −27%. **최근 5년(2021~)만 보면 연 9% / −27%** — 기대치는 이쪽으로 잡는다.
익절 없이 보유만 하면 같은 기간 연 13.1% / −49%(최근 5년 0.6%). 근거와 비교는 아래 '백테스트'.

## 자동 실행

| 작업 | 시각(KST) | 하는 일 |
|---|---|---|
| `daily` | 평일 08:37 (서버가 정각에 실행, GitHub 예약은 백업) | 시세·재무 → 점수·신호 → 대시보드·ntfy |
| `coin` | 4시간마다 :11 (서버가 정각에 실행) | 코인 탭·알림 |
| `collect` | 매일 00:07 | KRX 시세(고가·저가 포함)·DART 공시·소형주 재무 수집 → `data` 브랜치, DART 일괄 재무 변환, 팩터 탭·탭 카드 백테스트 재계산·배포, 분기 리밸런싱 날 0시 ntfy |
| `paper` | 평일 08:50 | **모의투자**(가상 60만 원, 위 전략 그대로) — 전 거래일 시가·고가로 매수·익절 체결 → ntfy, 상태 `docs/paper.json` |
| `ui` | `docs/` 바뀔 때 | 대시보드 배포 |
| `news` · `hold-reg` · `coin-reg` · `krx-renew` | 주간·수시 | 보유 종목 공시·뉴스, 보유·코인 등록 반영 등 |

GitHub 예약 실행은 30~60분씩 늦게 시작해서, 서울 서버(`hq`)가 정각에 '실행' 버튼을 대신 누른다. 서버가 먼저 실행했으면 늦게 온 예약 실행은 스스로 건너뛴다.

## 서울 서버 (`server/`, AWS Lightsail 13.124.17.147)

설치·업데이트: `curl -fsSL https://raw.githubusercontent.com/himk9094-png/hwandong-quant/main/server/install.sh -o hq.sh && sudo bash hq.sh` (이후엔 `hq update`)

| 명령 | 내용 |
|---|---|
| `hq status` / `hq check` | 예약·토큰 상태 |
| `hq token` | GitHub fine-grained 토큰(이 저장소만, Actions·Contents 읽기/쓰기) 입력 |
| `hq dartbulk` | DART '재무정보 일괄다운로드'(해외 IP 차단)를 받아 GitHub 릴리스 `dart-bulk`에 올림. 매주 월 23:30 자동 |
| `hq toss key` / `check` / `pick` / `tp` / `live` / `paper` | **토스 익절 봇**: 등록한 퀀트 종목에 '평균단가 +20%' 매도 조건주문을 평일 08:20·15:45에 맞춰 둠. 기본 모의 모드, 다른 종목·직접 건 주문은 안 건드림 |

UT봇(바이낸스 현물, `utbot/`)도 같은 서버에서 돈다(`utbot status`).
키(토스·바이낸스·GitHub)는 서버의 root 전용 파일에만 있고 저장소·채팅에 올리지 않는다.

## 데이터와 백테스트 방법 (`backtest/`)

- **시세**: KRX Open API 일별 전 종목(상장폐지 종목 포함), 2015~. 수익률은 `FLUC_RT`(권리락 조정), 고가·저가 포함
- **재무**: DART — 소형주는 API(실제 공시일), 상장사 전체는 일괄 파일(`bulk.py`, 공시일 대신 법정 제출기한 사용 = 보수적). 둘이 겹치는 값은 99.9~100% 일치
- **공시**: DART 공시 목록 → 🟡 = 최근 1년 유상증자·CB·BW·EB·감자 결정
- **엔진**(`smallcap.py`): 전날 종가 신호 → 다음 날 시가 체결, 재무는 공시 다음 거래일부터(TTM), 상장폐지는 마지막 거래가(정리매매 포함)로 현금화, 수수료 0.015%·매도세(연도별)·슬리피지 0.5%(편도). 익절은 그날 고가가 목표가 × 1.003 이상일 때만 체결로 봄
- 앱 데이터: `smallcap_app.py` → `docs/smallcap.json`(팩터 탭), `tabperf.py`·`sigbt.py` → `docs/tabperf*.json`(탭 카드)

### 주요 결과 (2016.4~2026.11, 비용 포함)
- 팩터 전략은 **소형주에서만** 통했다(연 8~17%). 중소형~대형 구간은 연 −7~+9%
- **+20% 익절은 소형주 전략 전부에서** 낙폭을 −48~52% → −21~39%로 줄였다. 대형주에는 오히려 손해
- 슈퍼퀄리티는 기간을 반으로 나눠도(2016~2020 / 2021~2026) 두 구간 모두 1등 → 운으로 고른 결과일 가능성이 낮다
- 앱의 종합(전체 시장)은 연 2.1%, 모멘텀·마법공식(전체 시장)은 손실. 코스피 소형으로 좁히거나 11~4월만 보유하면 좋아짐
- 매수신호·급등후보를 매매에 쓰면 비용 포함 손실(급등 다음 날은 평균 하락)
- 강환국 책의 연 37~40%는 2004~2016년 결과. 같은 규칙을 2016년 이후에 돌리면 크게 낮다

### 한계
- 초소형주는 호가가 얇아 지정가 체결 가정이 실제보다 좋을 수 있다
- 시총 구간은 10년 내내 같은 금액 기준, 일괄 재무는 공시일 근사
- 여러 설정을 시험했으므로(다중검정) 가장 좋은 숫자는 실제보다 높게 보일 수 있다
- 과거 성과이며 미래 수익을 보장하지 않는다

⚠️ 키는 직접 입력한다. 채팅·캡처로 공유하지 않는다.

4. **서버(선택)**: 위 설치 한 줄 → `hq token` → (토스) `hq toss key` → `hq toss check` → `hq toss pick` → `hq toss tp` → 확인 후 `hq toss live`

## 보유 탭
- 수량·평단은 **폰 브라우저에만** 저장된다(저장소·서버로 안 감). 브라우저 데이터를 지우면 사라지니 탭의 '백업·복원'으로 코드를 보관.
- 가격은 전 거래일 종가. 처음 열면 `config.json`의 `holdings` 종목을 불러오고, 한 번 저장하면 폰 목록이 기준이 된다.
- 종목을 더하거나 빼면 **종목코드·이름만** ntfy 등록 주제(`<ntfy_topic>-hold`, 구독 불필요)로 보낸다 → `hold-reg` 작업(1시간마다)이 `config.json`의 `holdings`를 바꾸고 ntfy로 확인 알림 → 주간 공시·뉴스 점검(`news`)과 다음 평일 계산의 '보유' 표시·차트에 반영. `holdings_t`(마지막 반영 시각)보다 새 메시지만 반영하므로 `config.json`을 손으로 고쳐도 옛 메시지로 되돌아가지 않는다.
- 종목 상세 화면의 '보유 종목에 추가'·'보유 수량·평단 수정'으로도 편집할 수 있다.

## 코인 탭
4시간마다(한국시간 01·05·09·13·17·21시 11분) `coin` 작업이 돈다. API 키·서버 필요 없음.

- **데이터**: 바이낸스 시세 전용 주소(`data-api.binance.vision`, 미국 서버에서도 열림) 일봉·4시간봉 + Coin Metrics 무료 커뮤니티 API(MVRV·해시레이트·채굴 발행액·거래소 순유입). 바이낸스 상장 전 구간은 Coin Metrics 종가.
- **온체인 국면**: BTC MVRV의 최근 4년(반감기 한 주기) 백분위 — 하위 20% 바닥권, 상위 20% 과열권. 2년 기준은 백테스트에서 실패해서 4년으로 바꿨다(과최적화 위험 있음).
- **프리셋**: 단순 보유 · 200일선 추세 · 역추세 기본(365일선 아래+RSI 30 미만 4분할 매수, 21일선이 365일선 +50%면 2분할 매도) · 역추세+온체인 · 온체인 단독 · UT Bot 일봉. 지표·전략 계산은 `docs/coin-engine.js` 하나를 브라우저와 알림이 같이 쓴다.
- **내 조합 전략**: 조건 전략(코인 비중·매수 조건 AND·매도 조건 OR·분할·2배 ETF 근사)과 전략 묶음. 폰 브라우저에 저장된다.
- **내 전략 알림**: 전략 화면의 '알림 받기'를 켜면 켠 전략 목록 전체를 ntfy 등록 주제(`<코인 주제>-reg`, 구독 불필요)로 보낸다. `coin-reg` 작업이 30분마다 새 등록을 확인해 `coin` 작업을 돌리고, `coin` 작업이 목록을 `coin.json`(state.mine)에 보관하며 매일 일봉 마감 후 새 매수·매도를 알린다. 서버 목록과 폰 목록이 다르면 앱이 열릴 때 다시 보낸다.
- **알림(ntfy)**: 코인 알림은 주식과 다른 주제(`config.json`의 `ntfy_topic_coin`)로 간다 — ntfy 앱에서 두 주제를 따로 구독. 대상은 `coin/config.json`에서 바꾼다. `alert_presets`×`alert_coins`의 매수·매도, `alert_ut4h` 코인의 UT Bot 4시간봉 전환, 온체인 국면 변화. 지난 상태는 배포된 `coin.json`에 남겨 같은 신호를 두 번 보내지 않는다.
- **UT Bot 설정**: `coin/config.json`의 `utbot`(일봉)·`utbot4h`(4시간봉) key·atr를 트레이딩뷰 설정과 맞춘다. 4시간봉은 기본 Key 5·ATR 20, 코인별로 `utbot4h.coins`에서 바꾼다(ETH 7·20 — 2018~2022로 고르고 2023~ 검증, SOL 5·20) (Key 1·ATR 10은 2018년부터 신호가 너무 잦아 손실). 일봉은 Key 2·ATR 20 (5·20이면 365일선 아래+MVRV 바닥권 조합 전략에서 매수가 0번이 됨).
- 로컬 실행: `NTFY_DRY=1 node coin/build.mjs` (Node 18 이상) → `docs/coinhist.json`, `docs/coin.json`
